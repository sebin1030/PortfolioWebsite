# Portfolio Website PRD

문서 버전: v1.0  
작성 목적: PM 취업을 위한 개인 포트폴리오 웹사이트 기획

## 1. 제품 개요

이 웹사이트는 PM 취업을 위해 수행한 프로젝트, 데이터 분석, 바이브코딩 결과물과 성장 기록을 한곳에 모은 개인 포트폴리오이자 온라인 명함이다.

핵심 메시지:

> 데이터를 기반으로 문제를 정의하고, AI를 활용해 빠르게 제품을 검증하는 Product Manager

## 2. 배경 및 문제 정의

현재 활동과 결과물이 여러 문서·저장소·링크에 흩어져 있어 방문자가 역량과 성장 과정을 한눈에 파악하기 어렵다. 특히 PM에게 중요한 문제 정의, 데이터 근거, 의사결정, 검증 과정을 일관된 형식으로 보여줄 공간이 필요하다.

## 3. 목표

### 핵심 목표

- 나를 소개하는 명함형 첫 화면을 제공한다.
- 프로젝트를 역량 중심으로 탐색할 수 있게 한다.
- 프로젝트의 과정과 의사결정 근거를 쉽게 확인하게 한다.
- 새로운 프로젝트를 지속적으로 추가할 수 있는 구조를 만든다.

### 성공 기준

- 방문자가 첫 화면에서 정체성·핵심 역량·대표 프로젝트를 이해한다.
- PM Projects, Data Analysis, Vibe Coding 세 카테고리를 명확히 구분한다.
- 각 프로젝트의 역할, 진행 형태, 결과물 링크를 빠르게 확인할 수 있다.
- 제한 공개 방식으로 공유 대상만 콘텐츠에 접근할 수 있다.

## 4. 사용자

### 1차 사용자: 나

- 프로젝트와 회고를 지속적으로 관리한다.
- 새로운 결과물을 쉽게 추가한다.
- 과거 활동과 성장 과정을 정리한다.

### 2차 사용자: 취업 담당자·면접관

- 짧은 시간 안에 지원자의 PM 역량을 파악한다.
- 대표 프로젝트의 문제 정의, 역할, 결과, 산출물을 확인한다.
- 필요하면 상세 문서·GitHub·Demo로 이동한다.

## 5. 접근 정책

사이트는 전체 공개가 아닌 제한 공개를 기본으로 한다.

### MVP 정책

- 모든 페이지는 비밀번호 인증 후 접근
- 공유 링크로 접속할 때마다 비밀번호 입력
- 로그아웃 기능은 구현하지 않음
- 잘못된 비밀번호에 대한 오류 안내
- 보호된 콘텐츠와 공유 링크의 무단 접근 방지

### 확장 정책

- 공유 링크를 보유한 사용자만 접근하는 토큰 기반 링크
- 링크 만료 및 폐기
- 필요 시 로그인 기반 접근

초기 구현은 공통 비밀번호 기반 접근을 사용한다. 추후 필요할 때 공유 링크 기반 제한 공개를 확장한다.

## 6. 정보구조(IA)

```text
Home

│   └── Project Detail
├── Data Analysis
│   └── Project Detail

│   └── Project Detail
└── Contact
```

### 상단 내비게이션

- About
- PM Projects
- Data Analysis
- Vibe Coding
- Contact

카테고리는 개인·팀 여부가 아니라 보여주고 싶은 역량 기준으로 나눈다. 개인/팀/공모전 정보는 프로젝트 카드와 상세 페이지의 메타데이터로 표시한다.

## 7. 페이지 구성

### Home

목적은 온라인 명함 역할과 핵심 탐색 제공이다.

- 이름 및 직무 타이틀
- 한 줄 소개
- 짧은 자기소개
- 핵심 역량: PM, Data, AI, Development
- 대표 프로젝트 카드
- 세 카테고리 바로가기
- 현재 진행 중인 일(Now)
- Contact 및 Resume 링크

### About

긴 이력서가 아니라 ‘어떤 방식으로 일하는 PM인지’를 보여준다.

- Hero: 이름, 직무 정체성, 한 줄 소개
- About Me: PM을 지향하게 된 배경과 관심 문제
- PM Philosophy: Problem → Data → Insight → Hypothesis → Product → Validation
- Skills: PM / Data / AI / Development
- Working Style: 문제 정의, 데이터 확인, 문서화, 협업·조율 방식
- Timeline: 주요 활동과 성장 과정
- Now: 현재 진행 중인 프로젝트와 학습
- Interests: Healthcare, AI, Product, UX, Data Analysis 등
- Contact: 이메일, GitHub, Resume 등

### 카테고리 목록 페이지

- 카테고리 설명
- 프로젝트 카드 그리드
- 태그 및 기본 메타데이터
- 대표 프로젝트 우선, 이후 최신순 정렬
- 프로젝트 상세 페이지 링크

### 프로젝트 상세 페이지

프로젝트마다 아래 흐름을 공통 템플릿으로 사용한다.

1. Executive Summary
2. Background
3. Problem
4. Research / Data
5. Insight
6. Hypothesis
7. Product Strategy
8. UX Flow / Wireframe
9. MVP / Implementation
10. Result / Validation
11. Retrospective
12. Links

### Contact

- 연락 목적 안내
- 이메일
- GitHub
- Resume
- 기타 공유 링크

## 8. 카테고리 정의

### PM Projects

문제 정의, 사용자 조사, 제품 전략, PRD, UX 설계, MVP 검증을 중심으로 보여주는 프로젝트.

예시: Medibuddy, PM Copilot, 서비스 기획 프로젝트

### Data Analysis

데이터 수집·정제·분석을 통해 인사이트와 제품 개선안을 도출한 프로젝트.

예시: 앱 리뷰 분석, 공공데이터 기반 서비스 제안, 사용자 행동 분석

### Vibe Coding

AI 도구와 바이브코딩을 활용해 빠르게 구현한 개인 실험과 인터랙티브 결과물.

예시: 포토부스, 고양이 데스크톱 펫, 랜딩 페이지, 미니 AI 도구

## 9. 프로젝트 카드 메타데이터

모든 카드에는 다음 정보를 일관되게 표시한다.

- 제목
- 한 줄 설명
- 카테고리
- 진행 형태: `Personal` / `Team` / `Competition`
- 기간
- 담당 역할: PM, 기획, 데이터 분석, 개발 등
- 기술·도구
- 상태: 진행 중 / 완료 / 보류
- 대표 결과물: 시연 화면과 기술 활용 내용
- 대표 이미지 또는 썸네일

## 10. 기능 요구사항

### MVP 필수 기능

- 비밀번호 기반 접근 제한
- Home, About, 세 카테고리 목록, 상세 페이지, Contact
- 프로젝트 카드 및 상세 템플릿
- Personal / Team / Competition 태그
- GitHub·Demo·문서 링크
- 반응형 레이아웃
- 프로젝트 콘텐츠 추가가 쉬운 데이터 구조
- 완성된 프로젝트만 등록·공개
- 진행 중인 활동은 About의 Now·Timeline에서만 표시

### 후순위 기능

- GitHub·Notion·Demo·Figma·문서 외부 링크 연결
- 공유 링크 토큰 및 만료
- 관리자 페이지
- Markdown 자동 등록
- 검색 및 태그 필터
- 방문 통계
- 다크모드
- 다국어 지원

## 11. 비기능 요구사항

- 데스크톱을 주 사용 환경으로 설계
- 모바일·태블릿에서도 콘텐츠를 확인할 수 있도록 반응형 지원
- 첫 화면과 목록의 빠른 로딩
- 키보드 탐색과 충분한 색상 대비
- 프로젝트 추가·수정이 쉬운 유지보수 구조
- 비밀번호와 보호 콘텐츠를 클라이언트에 노출하지 않는 인증 구조
- 링크 공유 시 핵심 정보가 깨지지 않는 안정적인 화면

## 12. 디자인 방향

- 개인 브랜드가 느껴지는 차분하고 명확한 화면
- 콘텐츠 우선의 여백 중심 레이아웃
- Home은 명함처럼 간결하게, 상세 페이지는 케이스 스터디처럼 깊게 구성
- 카테고리별 시각적 구분은 주되 전체 디자인 시스템은 통일
- 프로젝트 진행 형태는 작은 배지로 즉시 식별 가능하게 표시

## 13. 콘텐츠 운영 원칙

- 결과보다 문제와 의사결정 과정을 우선한다.
- 수치와 출처가 있는 데이터는 근거를 함께 기록한다.
- 프로젝트마다 본인의 역할과 기여 범위를 명확히 쓴다.
- 진행 중인 프로젝트도 상태를 표시해 지속적인 성장 기록으로 남긴다.
- 상세 내용은 길게 쓰기보다 핵심 요약 후 근거와 링크를 제공한다.

## 14. 개발 우선순위

1. PRD 및 콘텐츠 템플릿 확정
2. 접근 제한 구현
3. Home·About 구현 및 진행 중 활동의 Now·Timeline 표시
4. 카테고리 목록 및 프로젝트 카드 구현
5. 프로젝트 상세 템플릿 구현
6. 대표 프로젝트 등록
7. 데스크톱 중심 레이아웃 및 모바일 반응형·접근성 검수
8. 공유 링크, 검색 등 확장 기능 검토

## 15. MVP 완료 조건

- 제한된 사용자만 사이트에 접근할 수 있다.
- 모든 페이지 접근 전에 공통 비밀번호 인증이 필요하다.
- 로그아웃 기능 없이 접속 시 비밀번호를 다시 입력할 수 있다.
- Home에서 나와 대표 프로젝트를 이해할 수 있다.
- About에서 PM 정체성, 철학, 기술, 성장 과정을 확인할 수 있다.
- 세 카테고리에서 프로젝트를 탐색할 수 있다.
- 각 프로젝트에 Personal / Team / Competition 태그가 표시된다.
- 완성된 프로젝트만 목록과 상세 페이지에 노출된다.
- 진행 중인 활동은 About의 Now·Timeline에서 확인할 수 있다.
- 상세 페이지에서 문제부터 결과·회고까지 확인할 수 있다.
- 모바일 화면에서도 정상적으로 사용할 수 있다.

## 16. 서비스 흐름

### 기본 흐름

```text
공유 링크 접속
→ 비밀번호 입력
→ 인증 성공
→ Home
→ About / PM Projects / Data Analysis / Vibe Coding / Contact 선택
→ 프로젝트 목록
→ 대표 프로젝트 우선·최신순 정렬
→ 프로젝트 상세
→ 기획 과정·시연 화면·기술 활용 내용 확인
```

### 예외 흐름

```text
잘못된 비밀번호
→ 오류 메시지
→ 비밀번호 재입력

인증되지 않은 상태에서 내부 페이지 접속
→ 인증 화면으로 이동
→ 인증 성공 후 요청한 페이지로 이동

존재하지 않는 프로젝트 주소
→ 404 안내
→ 프로젝트 목록 또는 Home으로 이동
```

브라우저의 뒤로 가기 버튼은 브라우저 기본 동작을 사용한다. 왼쪽 상단 로고 또는 Home 버튼은 Home으로 이동한다. MVP에서는 외부 링크 연결을 제공하지 않는다.

## 17. 향후 검증 질문

- 방문자가 첫 화면에서 내가 어떤 PM인지 이해하는가?
- 담당자가 1분 안에 대표 프로젝트와 역할을 찾을 수 있는가?
- 프로젝트 카테고리 구분이 직관적인가?
- 상세 페이지의 정보량이 읽기 부담스럽지 않은가?
- 비밀번호 또는 공유 링크 방식이 실제 공유 상황에서 편리한가?
